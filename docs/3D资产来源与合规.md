# 3D 角色资产来源与合规说明

> 这份文档回答两个问题：**App 里能合法打包哪些模型**，以及**参考模型怎么用才不出事**。
> 起因是一份外部 3D 模型清单（见 `tools/model-inventory.pdf` 的解析结果），
> 里面的模型来源五花八门，必须逐条判定能不能进仓库。

## 一、结论先行

| 用途 | 能不能打包进 App | 说明 |
| --- | --- | --- |
| 可爱档原创角色 `assets/models/*.glb` | ✅ 可以 | 由 `tools/build-character.mjs` 程序化生成，版权归本项目 |
| **写实档原创角色 `assets/models2/*.glb`** | ✅ 可以 | 由 `tools/build-realistic.mjs` 程序化生成，版权归本项目（6 个：Elena / Mika / Aria / Marcus / Kai / Ren） |
| 用户自己导入的 `.glb` | ✅ 可以（本地） | 只在用户设备上渲染，不进 App 包，责任在用户 |
| 参考清单里的游戏 / 动漫角色 | ❌ 不可以 | 版权属于原作方，打包上架 = 侵权，商店会下架 |
| AAA / 参考模型（学习用） | ⚠️ 仅限本地学习 | 见第六节：可学做法，不可取其物 |
| 参考清单里的"授权可用"模型 | ⚠️ 逐个看 | 必须核对每个模型的 license，见第三节 |

### 清单里的面数提示

`606096 / 1521838`（Spellblade Queen）和 `984568`（某高模）这类数字说明
有些模型是**百万级面数**的高模。移动端单角色建议控制在 **3–5 万三角面**以内，
超了必须减面，否则低端机直接掉帧。本项目的程序化角色天然在几千面量级，不存在这个问题。

### Mixamo 的特殊情况

Mixamo（Adobe）的**角色和动画**在 Adobe 的条款下可以免费用于商业项目，
这是清单里唯一比较明确能用的来源。但注意：

- 用的是 **Mixamo 角色 + Mixamo 动画**，不能混入其他来源的网格
- Adobe 明确禁止把 Mixamo 资产**作为独立资产再分发**（比如做成模型包卖）
- 用在 App 里作为角色形象 ✅，单独售卖这些模型文件 ❌

本项目**没有直接采用 Mixamo 模型**，但采用了 Mixamo 的**骨骼命名规范**
（`mixamorig:Hips`、`Spine`、`LeftArm` …）—— 命名规范本身不受版权保护，
而且这样能零成本对接 Mixamo 的免费动画库。这是 `tools/autorig.mjs` 用 Mixamo 命名的原因。

## 四、本项目的做法：全部原创 + 程序化生成

`tools/build-character.mjs` 不下载任何模型，直接**程序化生成人形**：

```
预设参数（身高/肩宽/肤色/发型/服装色）
        ↓
几何生成（tube / ellipsoid 拼装人体）
        ↓
Mixamo 兼容骨架 + 蒙皮权重
        ↓
ARKit 命名的一套 blendshape
        ↓
assets/models/<id>.glb
```

好处：

1. **零版权风险** —— 完全自研，随便上架、随便商用
2. **五官位置已知** —— blendshape 才能做得准（给陌生 mesh 反推五官误差极大）
3. **顶点着色** —— 不依赖贴图文件，顺带解决原生端 three.js 贴图加载器不可用的问题
4. **可控迭代** —— 想要更写实，调参数即可，不用重新找模型

## 五、写实档是怎么做的

写实角色由**独立生成器** `tools/build-realistic.mjs` 产出（不是复用
`build-character.mjs` 改参数 —— 成人比例和 Q 版差得太多，共用一套几何函数
只会两边都别扭）。可爱档仍在 `assets/models/`，写实档在 `assets/models2/`。

| 维度 | 可爱版（Q版） | 写实版 |
| --- | --- | --- |
| 生成器 | `tools/build-character.mjs` | `tools/build-realistic.mjs` |
| 头身比 | 约 4.5 头身 | **7.4–7.9 头身**（实测，见下） |
| 身高 | 约 1.2–1.4 m | **1.66–1.86 m** |
| 绑定姿势 | A-pose（手臂下垂） | **A-pose**（上臂下倾 52°、前臂再折 12°） |
| 五官 | 大眼小鼻，扁平 | 立体鼻梁（鼻梁+鼻头+鼻翼）、颧骨、下颌 V 形收窄、唇形分 3 段 |
| 眼球 | 贴片 | **独立球体**（巩膜 + 虹膜 + 瞳孔 + 高光点 + 上下眼睑） |
| 头发 | 单块罩壳 | 分层：发际线罩壳 + 逐束 `tube()` 发束 + 长发垂落段 |
| 服装 | 单层色块 | 分层（外衣 / 内搭 / 下装 / 腰带 / 鞋），各自独立几何 |
| 肌肉 | 无 | 三角肌球 + 上臂隆起 + 前臂鼓 + 小腿肚 + 大腿 |
| 上色 | 单一色 | 顶点色多段渐变（颊红 / 手足偏黄 / 发梢提亮） |
| 面数 | 数千 | 1.9–2.0 万三角面 |
| 贴图 | `.jpg` + UV | **无贴图**，纯 `COLOR_0` |

### 为什么用 A-pose 而不是 T-pose

T-pose 是**绑定师调权重用的工作姿势**，人不会那样站着。早期版本的写实档
就是 T-pose，实测肩胸区（70~85% 身高处）的 X 跨度 / 总高达到 **0.89–0.95**，
而可爱档只有 **0.71** —— 观感上写实档"像一根衣架"，比可爱档还僵硬。

而 `rigDriver.js` 只叠加**相对位移**、不重置绑定姿势，姿势必须烘进几何里。
所以生成时直接按 A-pose 摆骨：肩点不动，整条手臂绕肩关节向下旋转。

| 姿势 | 肩胸区宽高比 | 腕下垂（相对身高） | 观感 |
| --- | --- | --- | --- |
| T-pose（旧） | 0.89–0.95 | 0.00 | 衣架感 |
| **A-pose（现）** | **0.62–0.72** | **0.27–0.28** | 自然放松 |

A-pose 也是 Mixamo 与主流 3A 角色管线的事实标准绑定姿势，
动画库（idle / walk / talk）本来就按 A-pose 绑定，重合度反而更高。

> 体检工具已经加了这两条断言（`poseRatio < 0.80`、`wristDrop > 0.18`），
> 以后谁把姿势改回 T-pose 会直接测试失败。

### ⚠️ 关于「极致写实」的诚实说明

需求原话是「**极致写实**」。这里必须讲清楚**做不到什么**：

- ❌ **达不到扫描级 / 毛孔级写实**。那是 photogrammetry（摄影测量）或
  MetaHuman 那种级别的资产，需要真实人脸扫描数据 + 数十万面 + 4K 贴图 + 法线/置换贴图。
  程序化几何在没有扫描数据的前提下，**物理上不可能**长出真实皮肤纹理和毛孔。
- ✅ **达到的是「雕塑级写实」**：真实成人人体比例（7.4–7.9 头身，经实测校验）、
  自然 A-pose 站姿、立体五官结构、独立眼球与高光、分层服装、肌肉起伏、
  顶点色渐变肤色。
  放在手机屏幕上、在 App 里这个尺寸（约 460×430 的 canvas）观看，
  观感是「一个比例正常、有立体感的成年人」，而不是 Q 版手办。

如果要**真正的照片级**，唯一合规路径是让用户自己导入扫描模型：

- 用户自己的扫描数据 → 本地渲染，不进 App 包，责任在用户（见第一节）
- 或采购有明确商用授权的扫描资产（如部分 CC0 扫描库 / 付费扫描包）

这条路径的接口已经预留：`PERSONA_MODELS` 是静态 `require` 表，
用户导入走的是另一条运行时加载分支。

## 六、AAA / 参考模型的使用边界（学习用途）

需求里明确说了「use AAA for learning purposes」。这里给出可执行的红线：

**可以做的（学习 / 研究）：**

- 在**本地、不进仓库**的目录里放置参考模型，用于：观察布线拓扑、研究
  蒙皮权重怎么布、对比头身比和五官比例、学习 LOD 与减面策略
- 把从中学到的**规律**固化成代码 —— 比如本项目写实档的
  三角肌球接缝处理、肘部半径咬合、分层发束，就是从真人模型结构里总结出来的
- 记录参数（头身比、肩宽比、腰臀比）用于校准程序化生成器

**绝对不能做的：**

- ❌ 把参考模型文件放进 `assets/` 或任何会被打包的目录
- ❌ 提取参考模型的网格 / 贴图 / 骨骼数据，直接或改头换面后用于本项目产物
- ❌ 把参考模型上传到任何公开仓库 / 分发渠道
- ❌ 用参考模型的**可辨识 IP 形象**（原作角色）去做角色的外观

一句话：**学习它的"做法"，不要拿它的"东西"。**

## 六、如果要引入外部写实模型

三条路，按推荐度排序：

1. **继续用程序化生成器调参**（推荐）
   零风险，且已经跑通全链路。缺的是美术细节，可以逐步加。

2. **买 / 下载明确可商用的模型**（CC0 或已购授权）
   要求：必须是**带骨骼的 glTF/VRM**，或能被 `autorig.mjs` 处理。
   入库前把 license 文件一并存进 `assets/models/<id>.LICENSE.txt`。

3. **用 3D 生成服务按图/文生成**（`tools/fetch_3d.py` 已支持）
   生成的模型版权归生成方条款约束，商用前确认服务条款。
   注意这类模型通常是**静态网格无骨骼**，需要走 `autorig.mjs` 绑骨。

## 七、用户自行导入模型的边界

App 内不做"上传并分发"的功能。如果将来加导入：

- 模型**只存在用户设备本地**，不上传、不进入任何资源包
- 界面上明确提示"请确保你有该模型的使用权"
- 服务端不存储、不分发用户上传的模型

这样 App 本身保持干净，责任边界清晰。
